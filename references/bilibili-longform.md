# B 站横版长视频（4–8 分钟）

竖版短视频那套管线大部分能直接用，差异集中在**结构**和**视觉调性**上。

## 规格

- 1920×1080 / 30fps
- 单期 4–8 分钟，系列化（一个主题拆 4 期递进比一期讲完好）
- 纯屏录 + 字幕 + 配音；BGM 按项目要求（默认无）

## 结构

```
钩子（前 5 秒）      一句话讲清「这期证明什么」，最好带数字
主线 5–6 段          每段 60–80 秒，一段一个论点
CTA                  链接/资源，画面停留 ≥ 2 秒让人记住
```

系列规划的递进逻辑（实践下来最顺的一种）：

```
第1期 立公信力 → 第2期 讲技术 → 第3期 讲广度 → 第4期 收商业闭环
"我们怎么证明"   "它怎么跑起来"   "你能玩什么"    "拳头功能是什么"
```

## 视觉调性：片内 vs 封面要分开

这是最大的一条 lesson：

- **片内**：讲论文/技术的题材，用学术图表风（白底 + 暖金 + 表格 + 误差棒，paper-figure feel）——
  符合题材，观众买账。
- **封面**：**必须爆款风**（毛笔字 headline + 高亮色块铺关键词 + 红印章 + 灰色 eyebrow 横条）。
  B 站观众不点学术风封面。

两者不矛盾。别因为内容严肃就把封面也做成学者风。

## 时间轴：audio-driven + 两端夹逼

长视频的段落里动画通常 3–5 秒就跑完，配音却可能 60 秒。规则：

```
target = 配音时长 + 呼吸（普通段 0.5s；结尾 CTA 段 2.0s 让 URL 停留）
video 比 target 长 → trim（动画早跑完了，trim 不影响）
video 比 target 短 → tpad 冻结末帧
```

早期用 `max(video, audio) + 0.3` 的逻辑，导致很多段视频长出音频一大截，
观感是「长时间停顿死寂」，被抱怨过。改成 audio-driven 后整片砍掉约 2 分钟。

## 字幕

同样必须 **1:1 跟音频每一句，不许漏行**。长视频句子多，更容易漏——
生成后拿字幕行数和口播拆句数对一遍。

结尾放链接的段落，字幕位置要抬高（比如 margin 从 160 提到 220），别压住 URL。

## 语速

长视频比短视频可以稍慢，但也别太慢：TTS 1.18 + `atempo=1.05` ≈ 有效 1.24×，
实测这个区间在 B 站听着舒服。

## 数据类内容的红线

引用的每个数字都要能追溯到出处，并且**注明版本/时间点**。
同一指标在不同时间点测出不同值是正常的（早期论文数据 vs 后续持续评测），
视频里要讲清楚「这是什么时候测的」，不要混着说。

**绝不自己编数字。**
