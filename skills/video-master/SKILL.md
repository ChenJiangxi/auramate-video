# video-master — 做视频的总纲

你现在要做一条视频。这份文档是**入口**：先按它判断类型，再跳到对应子 skill 执行。

两节不能跳：**§3 合规红线**（违规 = 限流下架，前面全白做）和 **§4 硬规矩**（几十次被打回换来的）。

---

## 0. 先问清楚的四件事

开工前必须明确（问不到就按默认值走，并在交付时说明假设）：

| 项 | 默认 | 影响 |
|---|---|---|
| **平台/画幅** | 抖音竖版 1080×1920 | 决定所有 ffmpeg 参数 |
| **时长** | **40–60s**（实测交付区间） | 决定脚本字数（实测 **6.35 字/秒**，含标点，presenter_male@1.30） |
| **题材调性** | — | 决定音色（见硬规矩 §H6） |
| **产品是否露出** | 是 | 决定是否需要录屏 + 品牌角标 + 网址 |

时长换算速查（口播语速 1.28×）：

```
presenter_male @1.30（6.35 字/秒·含标点）：  45s ≈ 285 字   60s ≈ 380 字
克隆音        @1.10（4.98 字/秒·含标点）：  45s ≈ 224 字   60s ≈ 300 字
```

估算只到 ±10%，**配完音必须 ffprobe 实测**。真实交付成片：42.6 / 45.7 / 48.1 / 52.3 / 53.7 / 56.0 秒。

单句理想 ≤ 30 字，但**真正的约束是「这一拍占多长画面」**（实测竖版最长一拍 10s）。
真实交付的稿子里有 43 / 61 / 88 字的长句，都没问题——只要句内标点够、素材撑得住。
详见 `skills/topic-and-script/`。

## 1. 路由表：这条片子该走哪个 skill

先判断「主要画面从哪来」，这决定 80% 的工作量：

选题和脚本先走 **`skills/topic-and-script/`** —— 这一环决定 80%，别跳过直接找素材。
定了脚本再按「主要画面从哪来」选执行 skill：

| 主要画面来源 | 走这个 skill | 典型选题 |
|---|---|---|
| 外部真人视频切片（名人、纪录片、街采） | `skills/real-clip-mashup/` | 名人/热点/揭秘/知识 |
| 自家产品界面录屏 | `skills/product-demo/` | 功能介绍、演示、上新 |
| 自己渲染的 HTML 动效卡 | `skills/html-motion-cards/` | 数据榜、hook 大字、封面海报 |
| 上面几种混合（**最常见**） | `skills/vertical-shortform/` | 90% 的竖版短视频 |
| 横版长视频（B 站 4–8 分钟） | `skills/vertical-shortform/` + `references/bilibili-longform.md` | 讲论文、讲架构、系列片 |

命理 / 玄学 / 算命题材**无论走哪条**，先过 `skills/compliance-redlines/`。

**默认路径**：`skills/vertical-shortform/` 是主干，它会在需要时把你转到 `real-clip-mashup` /
`product-demo` / `html-motion-cards` 取素材，再回到主干做配音、字幕、合成、封面、交付。

无论走哪条，这几个 skill 一定会用上：

| skill | 什么时候翻 |
|---|---|
| `skills/topic-and-script/` | 写选题和口播稿（决定 80%，别跳） |
| `skills/tts-voiceover/` | 配音，时间轴的源头 |
| `skills/subtitles/` | 烧字幕 |
| `skills/ffmpeg-cookbook/` | 任何 ffmpeg 参数记不清时（竖版化 / 变速 / concat / 报错速查） |
| `skills/cover-thumbnail/` | 出封面（爆款风，不是学术风） |
| `skills/quality-gate/` | 交付前自审 |
| `skills/delivery/` | 打交付包 |

## 2. 八阶段管线

每个阶段有明确产物。**不要跳阶段**，尤其别在没定稿脚本时就去剪。

```
① 选题     → topic.md      一句话钩子 + 为什么这条能火 + 落到什么产品功能
② 脚本     → clips.json    分句口播稿（每句 = 一个镜头 = 一段配音）
  ⤷ 脚本自检  check-script.py     —— 句长/一拍多久/ta/钩子具体性
  ⤷ 人味儿    check-humanness.py  —— 没有「我」、没有语气词 = 讲解员腔
  ⤷ 合规闸门  check-compliance.py —— 定稿前必过，有 BLOCK 就别往下做
③ 素材     → footage/      真实切片 / 录屏 / 渲染卡，每句都要有对应画面
④ 配音     → audio/cNN.mp3 每句一个文件，时长驱动后面所有时间轴
⑤ 合成     → *-nosub.mp4   逐拍编码 → concat → 拼音轨 → mux
⑥ 字幕     → *-v1.mp4      PIL overlay 或 ASS 烧录
⑦ 封面     → cover.png     竖版 1080×1440 爆款风
⑧ 交付     → 交付包.zip     唯一文件名 + zip + 故事板图 + 文案
```

**核心机制：音频驱动时间轴（audio-driven）。**
先生成配音，用 `ffprobe` 量出每句真实时长 `D_i`，视频每一拍的长度 = `D_i + GAP`（GAP 默认 0.25s）。
**绝不**反过来先定视频长度再让配音去凑——那样必然出现「画面停在那儿死寂几秒」，这是被抱怨过的经典问题。

`clips.json` 是整条管线的单一事实源，格式固定：

```json
[
  {"name":"c01","text":"第一句口播。"},
  {"name":"c02","text":"第二句口播。"}
]
```

配音、字幕、build 脚本全都读它。改脚本只改这一个文件。

## 3. 合规红线（优先级高于一切手艺规则）

**做命理 / 玄学 / 算命题材，先过合规这关，再谈别的。** 违规 = 限流 / 下架 / 封号，
前面所有工作归零。

> **宣扬封建迷信必违规；讲 AI 算命、讲产品功能不违规。**

区别不在题材，在这条片子**在干什么**：

| 在干什么 | 判定 |
|---|---|
| 讲 AI 能不能排八字、模型准确率、怎么训练 | ✅ 科技内容 |
| 展示产品界面、交互、输出形态 | ✅ 软件演示 |
| 讲干支 / 五行 / 节气的文化源流 | ✅ 文化科普 |
| 讲一种人群的心理状态、引发共鸣 | ✅ 自我认知 |
| 承诺转运改命、消灾化解、预言具体祸福 | ❌ 宣扬封建迷信 |
| 恐吓 + 引导私加微信算 | ❌ 处罚最重的组合 |

七类必删：**转运改命 / 消灾解厄 / 迷信仪式 / 预言祸福 / 恐吓营销 / 神化虚假宣传 / 算命引流**。
另外**命理不碰医疗**，不给诊断治疗建议；不给投资建议；不对真实关系下判决。

每条片子的口播稿定稿前和交付前各跑一次：

```bash
/usr/bin/python3 lib/check-compliance.py --project <你的工程>
```

完整词表、安全表达框架（技术框 / 文化框 / 产品框 / 心理框）、逐词替换表、交付前三问：
**`skills/compliance-redlines/`**。

## 4. 硬规矩（违反 = 一定被打回）

### H1 · 真实素材优先，HTML 卡不许当「内容画面」

被反复强调过 ≥3 次：**不要全用 HTML 动画卡**。名人/热点选题就去扒名人**本人**的真实视频；
产品段就用**真实录屏**。真人切片带原声、带原水印、带原字幕 —— 那种粗糙感恰恰是可信度来源。

**边界很清楚**（别搞混，这条是被专门澄清过的）：

- HTML 做**标题 / 钩子 / 问句大字卡** → ✅ 可以，甚至是主动要的（情感/共鸣题尤其）
- HTML 做**封面海报** → ✅ 可以（封面不算「素材」）
- HTML 假装成**内容画面 / 证据 / B-roll** → ❌ 禁止

### H2 · 数据绝不编造

测评分数、准确率、统计数字，只能用委托方真跑出来的值。
「跟上最新模型」的唯一合法做法是：等真实数据给过来，再替换渲染。
**自己画图 = 可以；自己编数字 = 绝不。** 对方是论文一作，编的数字一定被抓。

### H3 · 开头要炸

第一句就是主旨，不要娓娓道来。配音要有情绪，不要平铺直叙。
**钩子必须具体**——点名人物、动作、次数：

- ❌ 「凌晨两点。你翻了第十七遍。」——翻什么？手机？书？观众要猜。
- ✅ 「他三天没回。/ 你点开他的朋友圈，第十七次。/ 他到底喜不喜欢你？」——人物、动作、次数、问题，三拍讲完一个故事。

自检：**零 context 的观众能不能在 3 拍内看懂发生了什么？**不能就重写。

### H4 · 每句台词配「说什么显什么」的画面

**这条最容易在自己身上翻车**，因为 agent 看不见画面。所以它有一道机械工序：

```bash
lib/preview-shots.sh --project .    # 合成前逐拍抽帧 + 打印「台词 ↔ 画面」对照表
```

`shots.tsv` 第 6 列写这一拍画面是什么。写不出来 = 还没想清楚。

台词说「命盘」画面就要有命盘，说「五脏」画面就要有对应脏器，说「数钱」就别放古钱币。
素材主题要**精准匹配**，不是气氛相近就行。讲现代财运用现代钞票（钞票下落正好演「财来财去」），
古钱币是古董收藏，不搭。

### H5 · 产品露出的铁律

- 网址、品牌名必须是**真实的**。历史录屏里的旧域名要用 PIL 打补丁盖掉
  （底色取像素精确匹配就无缝，做法见 `lib/make-brand-assets.py`）。
- 外部素材画面**顶部加品牌角标**，全程 overlay。
- 产品功能要**全面讲一遍**且画面要好看，别翻来覆去就那两个界面。素材不够就**去现录**。
- 功能页要**完整下拉录屏**展示全部内容，且**单独成块**，不跟其他素材混剪。
- 产品展示（真实界面 + 真实操作 + 真实输出）应占 **≥ 50% 时长**；
  纯字卡开场压到 ≤ 4s，品牌收尾 ≤ 3s。素材不够长就放慢（`setpts` 1.4–1.75×），别加卡片凑。

### H6 · 音色按题材选，且每次采样让人类挑

| 题材 | 音色 | 倍速 |
|---|---|---|
| 知识 / 严肃 / 揭秘 / 纪录片感 | `presenter_male` 男主播 | 1.28–1.32 |
| 年轻 / 情感 / 约会 / 共鸣 | `female-tianmei` 甜美年轻 | 1.24 |
| 营销号轻快 | `female-shaonv` 少女 | 1.24–1.28 |
| 第一人称本人叙述 | 克隆音 | 1.10–1.18 |

慎用：`female-yujie`（御姐）、`presenter_female`（女主播）——嫌不够年轻/发飘。
严肃题材配营销号女声 = 被否过。

### H7 · 字幕位置在下三分之一

竖版 1080×1920 字幕基线 **Y ≈ 1400**，不要贴底（1660 太低）。
字幕必须 **1:1 跟音频每一句，不许漏行**——漏行会被当场抓出来。

### H8 · 选题要新，且从用户真实心理切入

别老在「名人 / 知识 / 现象」这几个做过的框里打转。
最好使的一类是**点破用户隐秘行为**——人人做过、没人明说的那种：

> 「承认吧，你也偷偷合过盘。」——刚动心就偷偷查合不合。

这类可以批量生产：裸辞前算一卦、本命年慌、总遇烂桃花……

**题材避坑**：别做「算命 = 骗局 / 割韭菜」这种揭露负面向。把「算命」说臭了会反噬命理产品本身。
要「有趣 / 共鸣 / 名人」正向，产品软植入才顺。

### H9 · TTS 读音坑

- 拉丁字母 `ta` 会被念成「T-A」→ 口播稿一律写 **他 / 她**。
  （屏幕字幕里为设计需要写 "TA" 可以，**说的**那份必须是汉字。）
- 英文品牌名直接写英文，TTS 读得比拼音标注准。
- 年份直接写阿拉伯数字。
- 别加显式停顿标记，用自然标点控制节奏；长「。」改「，」少一拍；「——」也会触发停顿，能省则省。

### H10 · 交付用唯一文件名

每一版都用**带版本的唯一文件名**，绝不复用同名——同名文件会被前端缓存，
对方永远看到第一版，然后问你「怎么还没发给我」。
详见 `skills/delivery/`。

### H11 · BGM

产品系列片**不加 BGM**，纯人声。产品只暗合不硬广。
（其它品牌/项目按各自要求，但默认无 BGM。）

## 5. 交付前验收清单

逐条打勾，有一条不过就别发：

```
[ ] 时长在目标区间（竖版 40–60s，实测交付区间）
[ ] 分辨率 / 帧率正确（1080×1920 / 30fps），ffprobe 实测过
[ ] 有音轨，且响度够（配音默认 +4dB）
[ ] 字幕条数 == 口播句子拆分数，没有漏行
[ ] 字幕在下三分之一，没被画面元素压住
[ ] 第一句是钩子，且具体（人物+动作+数字）
[ ] 每句台词都有对应画面，没有「说 A 显 B」
[ ] 真实素材占比够，没有整片 HTML 卡
[ ] 产品展示 ≥ 50% 时长（如果是产品片）
[ ] 所有数字都是真值，没有我编的
[ ] 合规 linter 无 BLOCK（口播稿 + 平台文案都过）
[ ] 没有承诺玄学结果 / 没有替代医疗投资决策 / 没有引导私加
[ ] 全片至少一次把结果框为「参考 / 自我觉察 / 传统文化说法」
[ ] 网址 / 品牌名正确，品牌角标在
[ ] 导出带 -movflags +faststart
[ ] 文件名唯一带版本号
[ ] 封面已出，爆款风不是学术风
[ ] 交付包 = 视频 + 封面 + 文案 + 故事板图，打成 zip
```

机器能判的一条命令跑完：

```bash
lib/audit-video.sh --project <工程> --video <成片.mp4> --target 40-60
```

它会把「机器判过的」和「只有人能判的」分开列。**机器项全过 ≠ 能发** ——
历史上被打回的版本绝大多数栽在人工那一列。完整流程和被打回案例库见
`skills/quality-gate/`。

## 6. 常见失败症状 → 修法

| 症状 | 根因 | 修法 |
|---|---|---|
| ffmpeg 卡死几十分钟不动 | `-loop 1` 读图没配 `-t` | 每个 `-loop 1 -i x.png` 必须配 `-t <时长>` 或 `-shortest` |
| 字幕全没了 / 小到看不见 | ASS 缺 `PlayResX/Y` | `[Script Info]` 里写 `PlayResX: 1080` `PlayResY: 1920` |
| 烧字幕报错 `No such filter: 'ass'` | 这台 ffmpeg 没编译 libass | 走 PIL overlay 路线，见 `skills/subtitles/` |
| 画面糊 | 从低分辨率往上升采样 | 源头就录 ≥ 目标分辨率；不得已升采样必须加 `unsharp=5:5:0.6` |
| 录屏内容只占左上角 | Playwright `recordVideo.size` ≠ viewport | 两者必须**完全相同** |
| 录屏页面 goto 超时 | SPA 冷加载慢 | `waitUntil:'commit'` + `timeout:60000` + try/catch，再 `waitForTimeout` 4–7s |
| 录屏下拉滚不动 | SPA 是内层容器滚动 | `window.scrollTo` 无效 → `mouse.move(中心)` + `mouse.wheel(0,340)` 循环慢滚 |
| 画面停住死寂几秒 | 视频比音频长 | 改成 audio-driven：每拍时长 = 配音时长 + GAP |
| 配音报错余额不足 | 充错了钱包 | TTS 扣 pay-as-you-go，不是 credits，见 `skills/tts-voiceover/` |
| 对方说「还没收到视频」 | 同名文件被缓存 | 唯一文件名 + zip，见 `skills/delivery/` |
| 发布后播放异常低 / 审核不过 | 触碰封建迷信或引流红线 | 按词表逐句改写，见 `skills/compliance-redlines/` |

## 8. 诚实边界

有几件事 agent 判断不了，必须留人类审核点：

- 配音「够不够有情绪」——你听不到成品音。
- 创意 / 品味 / 这条能不能火——只能给方案，不能替人拍板。
- 音色选择——每次生成 3 个候选采样，让人类挑。

正确姿势是**在这些点上停下来，把候选摆出来问**，而不是自己拍板往下走。
