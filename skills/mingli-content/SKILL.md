# mingli-content — 命理内容总纲

做灵伴（auramate）这一系列命理视频的专用文档。**先读这份定选题和论据，再回 `video-master` 走八阶段管线。**

命理是论据，不是主题。观众点进来是因为话题跟他有关，留下来是因为你说的话他没听过，转发是因为那句话替他说了他说不出口的立场。

## 一、两类内容，别混

| | 技术自证 | 泛话题 |
|---|---|---|
| 讲谁 | 讲产品 | 讲观众 |
| 观众反应 | "这家挺靠谱" | "这说的是我" |
| 作用 | 让犹豫的人下单 | 让陌生人点进来 |
| 例 | 八字取象 · 怎么让 AI 做好看 | 不上嫁才是大好命 · 十个日主十种活法 |

**两类都要做，但不要混在一条片子里。** 混了的结果：讲观众的部分不够狠，讲产品的部分像广告。

技术自证向按 `video-master` 正文的选题要求做即可。**泛话题向按下面的四层结构做。**

## 二、泛话题四层结构（缺一层就毙）

| 层 | 问题 | 判定 |
|---|---|---|
| **1 泛话题** | 不懂命理的人会不会关心？ | 婚恋 / 财富 / 命运 / 性格 / 关系。**不是**子平vs盲派、不是排盘精度 |
| **2 可争论的断言** | 有没有人会反对？ | 没人反对＝没人转发。中性描述（"八字里的十神"）直接毙 |
| **3 命理论据** | 能不能落到盘上／数据上？ | 落不到就是鸡汤。必须指得出是哪个字、哪一步大运、哪条统计 |
| **4 价值观落点** | 看完记住哪句话？ | 一句能被截图的立场。**不是**"欢迎使用" |

**自检**：把命理部分全删掉，第 2 层和第 4 层还立得住吗？
立得住＝好选题；塌了＝你在讲命理，不是在讲人。

## 三、价值观内核（三条，所有片子必须一致）

**任何选题的落点必须落在这三条之内**，否则片子之间会互相拆台。

**① 反戏剧** —— 真实的好，都是平的。
　　「正缘就是很无聊的」「生理性喜欢都是孽缘」属这一条。
　　对应产品：不夸大其词、默认平淡、不制造焦虑。

**② 反宿命** —— 盘说的是默认倾向，不是判决。
　　「换运就是换性格」是这一条的标准表述。
　　对应产品：十个日主「没有好坏，那是你处理事情时最默认的那个方式」。

**③ 重自主** —— 不替你做决定，也不替你定义什么叫好。
　　「不上嫁才是这个时代大好命」否定的不是上嫁，是"只有一种活法"。

### 落点必须归到灵伴身上（但不是硬广）

落点是**两句**，顺序不能反：

1. **价值观句** —— 三条内核之一，能被截图的那句。
2. **归位句** —— 一句话说明**灵伴正是这件事的执行者**，然后品牌落版。

```
✅ 「它能做的，是把『还要多久』从一团模糊，变成一个能查的年份」→ 灵伴 AI，陪你走出人生低谷
✅ 「灵伴不会为了好看，把平稳的说成戏剧的」
✅ 「灵伴敢把考砸的那部分也告诉你」
❌ 「所以快来用灵伴」「点击下载」「私信免费测」          —— 硬广/引流
❌ 只有价值观句、没有归位句                              —— 观众记住了观点，没记住谁说的
❌ 「所以你要努力」（鸡汤）「所以命就是这样」（宿命）
```

**判据**：归位句说的是**灵伴做了什么**，不是**要观众做什么**。前者是署名，后者是广告。

## 四、标题句式库

| 句式 | 例 | 适用 |
|---|---|---|
| **XX 有什么特征** | 上嫁有什么特征 | 群体画像，最稳，流量最大 |
| **XX 都是 YY 吗** | 富婆都是六亲缘浅吗 | 检验流传的说法，天然有争论 |
| **XX 到底存不存在** | 天生好命到底存在吗 | 立场题，评论区最活 |
| **XX 就是 YY**（断言） | 正缘就是很无聊的 · 换运就是换性格 | 最锋利，必须能自圆 |
| **不 XX 才是 YY** | 不上嫁才是这个时代大好命 | 价值观翻转，转发率最高 |
| **怎么过 XX** | 怎么过情关 | 实用向，收藏率高 |
| **我到底什么时候能 XX** | （已做） | 代入观众原话，钩子最直接 |

**三条纪律**
1. **用观众的词，不用行内的词**。写"富婆"不写"财旺身弱"；写"上嫁"不写"官星得地"。
2. **断言型标题必须能自圆**。说不清就换句式。
3. **不许"揭秘/震惊/千万别"**，那是另一条赛道，跟灵伴调子冲。

## 五、论据来源与取证纪律

按可信度排：

1. **生产库聚合统计** —— 11831 用户 / 27.8 万条提问。可查话题分布、问法分布、工具调用量。
2. **大赛真题 + 官方标准答案** —— `ra-bazi-test/projects/hkjfma-2026-competition/`，`score_all.py` 里有 GOLD。**唯一能当场验证的论据**。
3. **确定性排盘** —— `pan/pan_G*.md`，四柱/藏干/大运/引动逐字可查。
4. **代码与注释原文** —— metamate 仓库。讲机制时用。
5. **知识库** —— `dev-mangpai`：理法 14 / 象法 107 / 案例 184（源头是 `data/knowledge/manifest.json`）。

### 取证纪律（都是真踩出来的）

- **查生产库只取聚合计数，不导出对话内容。** 要引用原话必须先跟 Jessy 说明，且去掉一切可识别信息。
- **正则统计会严重虚高。** 「谢谢」多数是客套、「好多了」在说身体、「有用吗」是提问。
  报数前先抽样看原文，否则你会把 1257 条客套报成"用户好评"。
- **注释与实现不符时，一律以实现为准。** 本系列已抓到三处：
  `worker:82` 写"约 10 粒金币"实际是 `hash < 0.006`（千分之六，约 4–7 粒）；
  `init.ts:20` 写"粒子采样仅用 280px"实际 `sampleSize = 320`；
  `spirit-particle-forms.md §12` 的 5 光行为方案已被代码里的 13 种取代。
- **数字是 Jessy 的真跑数据，一个都不许改。** 她要求把 21 分说成 22 分时应当拒绝；
  只有当她明确说明"是记录出错"并给出依据时才改，且要在 SCRIPT.md 里写明出处。
- **做不出来就说做不出来。** 曾被要求做"好评合集"，但库里整句是夸奖的不到 20 条，
  且多为对话客套——正确做法是如实报告并给替代方案，不是拼凑。

## 六、命理特有的画面语言

### 五行入排版（最有效的一招）

**每个干支按自己的五行上色**：木青 `#1f8a5b` · 火赤 `#c8402f` · 土黄 `#a8791a` · 金灰 `#6b7280` · 水蓝 `#2a5ea8`。

配一张**五行统计条**（全盘 20 字 = 4 天干 + 4 地支 + 12 藏干）。
真实案例：G2 盘统计出来是 土9 / 金6 / 水3 / 火2 / **木0**——木那根条是空的，
"一个木都没有（夫星不透）"这句话**不用说，画面自己在喊**。后面流年乙木一透，
那抹绿是全片第一次出现绿色，视觉上就是"它终于来了"。

### 真盘 > 示意图

`pan_G*.md` 直接渲染（大运每步带十神/纳音/长生/空亡/神煞 + 对原局引动）比任何自制图表都有说服力。
**但录屏必须裁掉浏览器地址栏**（见 §七）。

### 代码页录屏：从真文件渲染，不手写复刻

`script/mkcode.js` 的做法：读磁盘原文 → 极简着色 → 渲成编辑器窗口页 → 用
`lib/rec-frames.js --cursor arrow --act` 录，光标停在旁白正在说的那一行。
**内容一个字都不能手打**，否则就是"复刻"不是"证据"。

### 排版：铺垫句灰、扎人句白加粗

一句白描拆成两行：上句铺垫（40px / 62% 白），下句扎人（52px / 纯白 / 800）。
**断行必须手动定**，否则会出现"就烧不动/了"这种把词拆开的情况。

## 七、本系列踩过的坑

### ① 画面里出现网址 = 引流违规（最贵的一次）

平台判的是**"出现网址"这件事本身**，不是网址对不对。
真实事故：一条片子中段用了盲派站点录屏，浏览器**地址栏**里印着域名 → 被判引流。
只改落版页没用，全片任何一帧都不能有。

> ⚠️ 这条与 `quality-gate` 里「录屏地址栏是旧域名 → 打补丁盖成正确域名」的建议**冲突**。
> 以本条为准：**去掉，不是改对**。

**排查方法**（base64 图片数据里会混进 `http` 字样，必须先剥掉再查）：

```python
s = re.sub(r'data:image/[a-z]+;base64,[A-Za-z0-9+/=]+', '[IMG]', s)
re.findall(r'https?://\S+|(?<![A-Za-z0-9])[a-z0-9-]+\.(?:com|net|cn|org)(?![A-Za-z0-9])', s)
```

裁掉地址栏：`crop=1776:999:72:80,scale=1920:1080`（1920×1080 录屏，chrome 高约 80px）。

### ② zoompan 会抖，2 倍预放大不够

`ffmpeg-cookbook` 说"先放大 2 倍再 zoompan，否则会抖"——**2 倍仍然抖**。
成因：zoompan 每帧把裁切窗口的 x/y 取整到像素，1080 尺度下就是一帧一跳的 1px 位移。

实测（灵体区帧间差，32×32 灰度均值）：

| 做法 | 抖动 |
|---|---|
| 直接 zoompan | 明显可见 |
| 预放大 3 倍（5760×3240）再 zoompan | **0.105** |
| 完全静止 | **0.000** |

**Jessy 说"不要抖"时，唯一可靠的答案是完全静止**。要运动感就用交叉溶解（几何上不动）。

另一个隐患：把 3:1 的长图直接 `zoompan ... s=1920x1080` 会**纵向硬拉**。
正确做法：先等比缩放再 pad 到 16:9，让 zoompan 的输入本身就是 16:9。

### ③ 灵体必须先唤醒

页面写着「轻触灵体 · 唤醒今日灵相」。**睡着的灵体是废素材**（已踩两次）。
唤醒点：`p.mouse.click(959, 166)`（1920×1080 视口）。唤醒后会弹今日灵签卡，
卡上带形态名 + 「丙午年 · 丙申月 · 辛酉日」，是很好的实证画面。

### ④ 换灵体图不用改库：浏览器层拦截

本地 dev 的测试号没有真灵体图，用的是 `picsum.photos` 占位图（所以录出来一直是灰暗风景）。
想录不同灵体的粒子动效，**不改数据库不改代码**：

```js
await ctx.route('**picsum.photos/**', r => r.fulfill({status:200, contentType:'image/png', body: buf}));
```

粒子采样、物理全走产品自己的逻辑，只是换了张源图。

### ⑤ 调试面板是 dev-only

`NODE_ENV !== "production"` 才渲染，线上没有。切十神形态/情绪要在本地 dev 跑。
入口选择器 `[data-testid="debug-panel-toggle"]`；面板打开后该元素消失，
**再点它是关不掉面板的**（曾导致 10 段录屏里面板一直开着）。

### ⑥ 字幕带与卡片底部会撞

字幕基线 y=920（50–52px 字）时，与 `base.css` 里 `.foot`（bottom:62）重叠。
新建卡片时把结论行放到 y<894 或改用独立落版页。

### ⑦ 交付：聊天附件上限 25MB

代码/文字类画面熵高，1080p CRF19 很容易到 40–70MB。压缩阶梯（实测文字无可见劣化）：

| CRF | 236s 片长 |
|---|---|
| 19（原片） | 67.6 MB |
| 24 | 37.7 MB |
| 27 | 26.5 MB |
| 28 | 23.6 MB |
| 30 | 23.2 MB（276s） |

**发聊天的是压缩版，无损原片留在 `out/video-subs.mp4`，发布用那个。** 每次都要说明。

### ⑧ 语速

克隆音 `--speed 1.15` 实测约 4.4 字/秒，Jessy 嫌慢。
**`--speed 1.26–1.32` → 5.75 字/秒**，同一份稿子从 149s 压到 115s。

### ⑨ 封面别用 AI 生图

4 字巨标会把宋体的横细竖粗拉变形（"象"字尤其糊）。
**本地用真 Songti SC 排版**：字形是字库原样，字号字距可精确控制，改字重截一张就行，
不用开 codex、不用赌模型写不写得对字。

## 十、每条片子的固定动作

- **先写落点，再写开头**。落点必须是三观之一。
- **开头用观众的原话**。「我到底什么时候能……」比「今天聊聊应期」强十倍。
- **命理术语出现前先给人话**：先说"她的感情不会自己动"，再说"夫星不透"。
- **涉及低谷/情绪的选题必须带边界句**：「它能陪你，但它不是治疗——真难受到那个程度，要去找人」。
  越是把落点做成"陪你走出低谷"，这句越不能省：它不是削弱承诺，是让承诺可信。
- **全片不出现网址**（§七①）。
- 合规过 `check-compliance.py --strict`；「吉凶」这类词即使用在否定句里也会被 WARN，换成"断语"。

## 附：一个未闭合的产品风险

`intent-detection.ts` 的强情绪词表里收了「想死」「活不下去」「厌世」「自杀」，
但它们**只用于路由到 emotional_support 和给 emotionLevel 加分**——
全仓没有危机处理路径（无热线、无升级、无边界 prompt）。

做"陪你走出低谷"这类把低谷人群往产品里引的片子时，这件事必须先跟 Jessy 说清楚。
内容层的边界句是补丁，不是产品层真的有。
